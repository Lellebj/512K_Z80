install quartus ii 13.0sp1 on linux mint 22.3

Prerequisites & Dependencies
Quartus II 13.0sp1 relies on older libraries no longer present by default in modern Ubuntu/Linux Mint 22.x baselines.

    Enable 32-bit architecture support in APT:
    bash

    sudo dpkg --add-architecture i386
    sudo apt-get update

    Använd koden med försiktighet.
    Install required system and compatibility packages:
    bash

    Använd koden med försiktighet.

Unable to read device chain (Hardware not attached)
The error Unable to read device chain (Hardware not attached) means Quartus successfully sees your USB-Blaster hardware, but the underlying JTAG server (jtagd) cannot communicate with the FPGA chip or lacks permission to parse the device list. 
Follow these steps sequentially to resolve the issue on Linux Mint:
1. Fix Permissions (udev Rules)
If Linux lacks permissions to access the USB device, the JTAG server will fail to initialize the chain. 

    Create or open the udev rule file:
    bash

    sudo nano /etc/udev/rules.d/51-usbblaster.rules

    Använd koden med försiktighet.
    Paste the following configuration exactly (covers standard and clone USB-Blasters):
    text

    # Altera USB-Blaster
    SUBSYSTEM=="usb", ATTR{idVendor}=="09fb", ATTR{idProduct}=="6001", MODE="0666"
    SUBSYSTEM=="usb", ATTR{idVendor}=="09fb", ATTR{idProduct}=="6002", MODE="0666"
    SUBSYSTEM=="usb", ATTR{idVendor}=="09fb", ATTR{idProduct}=="6003", MODE="0666"

    # Altera USB-Blaster II
    SUBSYSTEM=="usb", ATTR{idVendor}=="09fb", ATTR{idProduct}=="6010", MODE="0666"
    SUBSYSTEM=="usb", ATTR{idVendor}=="09fb", ATTR{idProduct}=="6810", MODE="0666"

    Använd koden med försiktighet.
    Save and close (Ctrl+O, Enter, Ctrl+X).
    Reload the rules and re-plug your USB-Blaster:

    sudo udevadm trigger

No parameter named JTAGClock
The error "No parameter named JTAGClock" occurs because older versions of the JTAG daemon (like the one bundled with Quartus 13.0sp1) do not support the JTAGClock parameters natively, or the parameter names differ in legacy builds.
Let's skip that parameter and fix the issue using a known workaround for modern Linux kernels and USB-Blaster clones.
1. The usbfs Memory Limitation Fix
Modern Linux distributions (including Mint 22.x) limit the memory size allocated for USB transfers (usbfs_memory_mb), which frequently breaks the communication buffer of Altera USB-Blasters on newer kernels.

    Check your current USB memory allocation limit:
    bash

    cat /sys/module/usbcore/parameters/usbfs_memory_mb

    Använd koden med försiktighet.
    If it returns 16 (the default), temporarily increase it to 1000:
    bash

    sudo sh -c 'echo 1000 > /sys/module/usbcore/parameters/usbfs_memory_mb'

    Använd koden med försiktighet.
    Restart the JTAG server and test again:
    bash

    killall -9 jtagd
    /opt/altera/13.0sp1/quartus/bin/jtagconfig

    Använd koden med försiktighet.

Note: If this fixes your issue, you can make it permanent by adding usbcore.usbfs_memory_mb=1000 to your GRUB boot options.
2. Force jtagd to Access the Ports Directly
Sometimes the JTAG server runs into internal permission constraints even after configuring udev rules. Forcing the server to run with administrative permissions will bypass this boundary completely.

    Kill any existing instances:

    killall -9 jtagd

    Använd koden med försiktighet.
    Launch the JTAG daemon as root:
    bash

    sudo /opt/altera/13.0sp1/quartus/bin/jtagd

    Använd koden med försiktighet.
    Run the config utility as a standard user:
    bash

    /opt/altera/13.0sp1/quartus/bin/jtagconfig

    Använd koden med försiktighet.
